# Tunnel Mesh 探路链 — 递归规划 + 一键输出

## 当前问题

`phase2-chain.sh` 只是简单问「当前能连谁」，没有：
- 递归选方向（A连B 还是 B连A）
- 统一端口管理
- 根据链自动推导全部配置
- 输出教程/脚本

## 优化目标

一次探路链完成后，自动生成：
1. 每台服务器的 SSH config 条目
2. 每台服务器的隧道维持命令
3. 密钥部署清单
4. 开机自启配置
5. 端到端验证命令

## 交互流程

```
[2]边规划 → 双方不能互连 → [3]探路链

目标: A → D
统一端口 [4001]:

────────────────────────────────

步骤1: A 能直连 D 吗？
  → 检测/询问 → 不能

步骤2: 加一个中继服务器
  名称: B
  B和A 谁连谁？
    [1] A连B（正向）  [2] B连A（反向）
  选 [2] → B→A 反向隧道

步骤3: 当前节点 B，B 能直连 D 吗？
  → 不能

步骤4: 再加一个中继
  名称: C
  B和C 谁连谁？
    [1] B连C（正向）  [2] C连B（反向）
  选 [1] → B→C 正向

步骤5: 当前节点 C，C 能直连 D 吗？
  → 能 → 正向

────────────────────────────────

链完成: A ←─R─ B ──F─→ C ──F─→ D
         :4001     :4001    :4001

════════════════════════════════════
  生成配置文件...
════════════════════════════════════

[1/1] 密钥部署清单
────────────────────
B的公钥 → A  (隧道维持)
B的公钥 → C  (隧道维持)
C的公钥 → D  (隧道维持)
A的公钥 → D  (端到端认证)

[2/1] A 上的配置
────────────────────
SSH config:
  Host D
      HostName localhost
      Port 4001

[2/2] B 上的配置
────────────────────
隧道进程（需开机自启）:
  ssh -R 4001:localhost:4001 user@A -N
  ssh -L  4001:localhost:4001 user@C -N

SSH config:
  Host C → forward
  Host D → ProxyJump C

[2/3] C 上的配置
────────────────────
隧道进程:
  ssh -L 4001:localhost:22 user@D -N

SSH config:
  Host D → forward

[2/4] D 上的配置
────────────────────
  不需要额外配置

[3/1] 验证
────────────────────
A: ssh D hostname

════════════════════════════════════
  教程已生成: ~/chain-A-D.md
════════════════════════════════════
```

## 技术实现

- 递归函数 `plan_hop(current, target)` 
- 每跳判定方向（正向/反向），记录到 `hops[]` 数组
- 统一端口：第一跳用端口 P，后面全部 `-L P:lo:P`
- 链完成后 `generate_chain_output()` 遍历 hops[] 生成全部输出
